# Поделим — MVP (Эпоха 1)

Умный калькулятор долгов для компании в кафе/ресторане. Фото чека → позиции
разложены автоматически (через vision-модель) → каждый участник в Telegram
отмечает, что заказывал → в конце видно, кто сколько должен. Деньги внутри
MVP **не двигаются** — чистый калькулятор (как Splitwise), без статуса
финансового посредника. Переводы участники делают сами, например обычным
переводом на карту создателю счёта.

Этот README написан в расчёте на то, что ты **не программист** — весь код
уже написан, тебе нужно только пройти шаги ниже (создать несколько бесплатных
аккаунтов и скопировать несколько значений). Если на каком-то шаге появится
непонятная ошибка — просто пришли её текст обратно в чат, разберём.

---

## Итоговая схема (что где живёт)

- **Код** — хранится на GitHub (бесплатно, без карты).
- **Backend** (мозг приложения — API + телеграм-бот в одном) — хостится на
  Render.com (бесплатно, без карты, с оговоркой ниже про "засыпание").
- **Frontend** (сама страница Mini App) — хостится на GitHub Pages
  (бесплатно, без карты).
- **Распознавание чеков** — Google Gemini API (бесплатный лимит).

Ничего из этого не требует привязки банковской карты. Единственная реальная
трата — если бесплатного лимита Gemini не хватит (см. раздел ниже), но
начать можно совсем без денег.

## Шаг 0. Забронировать 60–90 минут

Первый прогон по всем шагам займёт около часа — дальше, если что-то менять
в коде, повторный деплой будет занимать 1–2 минуты.

## Шаг 1. Создать бота в Telegram (5 минут)

1. Открой в Telegram чат **@BotFather**.
2. Отправь `/newbot`, придумай имя и username (username должен заканчиваться
   на `bot`, например `podelim_uz_bot`).
3. BotFather пришлёт токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxx`.
   Сохрани его — это `BOT_TOKEN`.

## Шаг 2. Получить бесплатный ключ для распознавания чеков (5 минут)

1. Зайди на **aistudio.google.com**, войди через Google-аккаунт.
2. Нажми **Get API key** → **Create API key**. Скопируй ключ — это
   `OPENAI_API_KEY` (да, называется так в коде, хотя ключ от Google — так
   исторически называется формат протокола, который использует и Google, и
   OpenAI, и многие другие; это не ошибка).
3. **Важная проверка именно для Узбекистана**: доступность Gemini API по
   регионам иногда меняется. Если при создании ключа или при первом запросе
   увидишь ошибку про недоступность региона — не паникуй, есть запасные
   варианты, см. раздел "Если Gemini не работает" ниже.

## Шаг 3. Выложить код на GitHub (10 минут)

1. Зарегистрируйся на **github.com** (бесплатно, без карты).
2. Нажми **New repository**, назови, например, `podelim`, оставь Public
   (или Private — не принципиально), создай.
3. На странице репозитория — **Add file → Upload files**, перетащи туда
   ВСЕ файлы и папки из архива, который я прислал (`backend/`, `frontend/`,
   `README.md`). Commit changes.

## Шаг 4. Задеплоить backend на Render (15 минут)

1. Зайди на **render.com**, зарегистрируйся через GitHub-аккаунт (кнопка
   "Sign in with GitHub") — карта не требуется.
2. **New → Web Service**, выбери свой репозиторий `podelim`.
3. Настройки:
   - **Root Directory**: `backend`
   - **Runtime**: Python 3
   - **Build Command**: `pip install -r requirements.txt`
   - **Start Command**: `uvicorn main:app --host 0.0.0.0 --port $PORT`
   - **Instance Type**: Free
4. Ниже, в **Environment Variables**, добавь (значения — из шагов 1–2 и
   `backend/.env.example`):
   ```
   BOT_TOKEN=<токен из шага 1>
   OPENAI_API_KEY=<ключ из шага 2>
   OPENAI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai/
   VISION_MODEL=gemini-2.5-flash
   USE_WEBHOOK=true
   WEBHOOK_SECRET=<любая случайная строка, придумай сама/сам>
   MINI_APP_URL=https://example.com   (пока заглушка, поправим в шаге 5)
   PUBLIC_BACKEND_URL=https://example.com   (пока заглушка, поправим ниже)
   ```
5. Нажми **Create Web Service**. Дождись первого деплоя (2–5 минут).
6. Render покажет реальный адрес вида `https://podelim-xxxx.onrender.com` —
   это твой `PUBLIC_BACKEND_URL`. Зайди в **Environment**, впиши туда этот
   реальный адрес вместо заглушки, сохрани — Render передеплоит сервис сам.

⚠️ **Особенность бесплатного тарифа Render**: если сервисом никто не
пользовался 15 минут, он "засыпает", и следующий запрос будит его около
минуты. Для теста с друзьями это нормально (первое сообщение боту после
паузы просто придёт с задержкой), для полноценного запуска позже стоит
перейти на платный тариф ($7/мес) или другой хостинг.

## Шаг 5. Задеплоить frontend на GitHub Pages (10 минут)

1. Перед публикацией открой в репозитории на GitHub файл
   `frontend/index.html`, нажми на иконку карандаша (Edit), поправь два
   значения прямо в браузере:
   - `const API_BASE = "https://YOUR-BACKEND-DOMAIN.example.com";` →
     впиши туда адрес из шага 4.6 (`https://podelim-xxxx.onrender.com`).
   - `const botUsername = "YOUR_BOT_USERNAME";` → впиши username бота
     из шага 1 (без `@`).
   - Сохрани (Commit changes).
2. В репозитории: **Settings → Pages**. В "Build and deployment" выбери
   **Deploy from a branch**, ветка `main`, папка `/` (root). Сохрани.
3. Через минуту-две GitHub покажет адрес вида
   `https://твой-username.github.io/podelim/frontend/index.html` — это
   твой `MINI_APP_URL`.
4. Вернись в Render → Environment → впиши этот адрес в `MINI_APP_URL`
   вместо заглушки, сохрани (передеплоится сам).

## Шаг 6. Привязать Mini App к боту (5 минут)

1. В чате с **@BotFather**: `/mybots` → выбери своего бота →
   **Bot Settings → Menu Button → Configure Menu Button**.
2. Пришли ссылку из шага 5.3 (`MINI_APP_URL`).
3. Готово — теперь у бота внизу есть кнопка, открывающая Mini App.

## Шаг 7. Проверить (5 минут)

1. Напиши своему боту `/start` в Telegram.
2. Подтверди номер телефона по кнопке.
3. Нажми кнопку открытия приложения, сфоткай любой чек (или чек из
   интернета, любой, лишь бы были позиции и итог).
4. Проверь, что позиции распознались верно и итог совпадает с чеком.
5. Открой ту же ссылку с другого аккаунта (или попроси друга) и проверь,
   что можно отметить свои позиции и получить точный расчёт.

Если что-то не срослось — самая частая причина в 90% случаев: не тот адрес
вписан в `API_BASE`/`MINI_APP_URL`/`PUBLIC_BACKEND_URL` (лишний слэш,
http вместо https, старая заглушка). Проверь эти три значения в первую
очередь.

## Если Gemini не работает из Узбекистана

Запасные варианты, для которых менять код НЕ нужно — только эти три строчки
в Environment на Render:

- **OpenRouter** (openrouter.ai) — агрегатор моделей, есть бесплатные
  vision-модели, регистрация без карты. `OPENAI_BASE_URL=https://openrouter.ai/api/v1`,
  модель — уточнить в их каталоге актуальную бесплатную vision-модель на
  момент регистрации (список меняется).
- **Groq** (groq.com) — бесплатный тариф, быстрые ответы, тоже
  OpenAI-совместимый. Проверить на момент регистрации, какая vision-модель
  доступна бесплатно.
- Если совсем ничего бесплатного не завелось — платный `gpt-4o-mini` от
  OpenAI стоит доли цента за фото, при тесте на друзьях (десятки чеков)
  выйдет в пределах 1 доллара суммарно.

## Ограничения этой версии (осознанно, ради быстрого старта)

- Деньги не двигаются — только расчёт долгов (соответствует твоему решению
  про запуск без банка-партнёра/юридической рамки).
- Backend на бесплатном Render засыпает при простое (см. шаг 4).
- Один язык интерфейса (русский) — сама модель распознаёт узбекский текст
  на чеке, но кнопки в приложении пока по-русски.
- Нет автообновления экрана между участниками — надо обновить вручную
  (потянуть/перезайти).

## Следующие шаги после теста с друзьями

1. Прогнать 20–30 реальных чеков из ташкентских кафе/базаров, посчитать,
   часто ли модель ошибается в суммах/позициях — это покажет, тянет ли
   бесплатный план или пора закладывать бюджет на распознавание.
2. Собрать обратную связь по самому неочевидному месту в UX — как удобно
   отмечать "это блюдо мы делили с Аней и Бехзодом".
3. Только после этого — решение по Эпохе 2 (реальный сбор денег): это уже
   не 1–2 недели, а отдельный трек с юристами и банком-партнёром/НКО
   (см. документ "Групповые платежи").
